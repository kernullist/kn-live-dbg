# KMON 보조 이미지 뷰 재배치 기준 검증 (2026-10-23)

기준 커밋은 `7f717cf`다. [직전 검증](KMON_LAYOUT_FRESHNESS_VALIDATION_20261023.md)에서
보조 뷰를 현재 매핑 주소로 재배치하면 실제로 없는 코드 변경을 만들 수 있음을
확인하고 `live_image_relocation_base_ambiguous`로 보류했다. 이번 변경은 검증 근거가
있는 보조 뷰의 바이트 비교를 복구한다. 증거 디렉터리는
`.build/kmon-secondary-view-20261023`이다.

## 근거와 구현

테스트 PC에서 `System.Data.dll`과 x64 실행 파일·시스템 DLL을 실행 없이 두 번씩
매핑했다. 매핑 주소가 달라도 OS가 만든 헤더의 ImageBase는 같은 재배치 주소를
가리켰다. `local-mappings.json`에는 PE32 `System.Data.dll`의 디스크 선호 주소
`0x10000000`, 독립 뷰 주소 `0x0a9a0000`·`0x0ad00000`, 헤더 재배치 주소
`0x74200000`과 초기 포인터 바이트가 기록돼 있다. 이 주소는 이전 실행의 값과
다를 수 있으며 프로그램에 고정하지 않는다.

헤더의 제3 주소를 대상 메모리만으로 승인하지 않는다. 전체 이미지 순회는 다음
조건에서만 독립 뷰의 기준을 사용한다.

1. 기존 PE/PDB 식별자와 파일 식별자 검사를 통과하고, 참조 파일 핸들을 쓰기·삭제
   공유 없이 읽기 전용으로 유지한다.
2. 이 핸들로 이름 없는 `PAGE_READONLY | SEC_IMAGE_NO_EXECUTE` 매핑을 만든다.
   DLL 초기화나 진입점 실행은 하지 않는다. 독립 뷰의 PE/PDB 식별자가 일치하고
   헤더 기준이 대상의 제3 주소와 같아야 한다.
3. 기대값은 계속 디스크 원본과 재배치 표에서 계산한다. 해당 페이지에 걸친 모든
   재배치 바이트를 독립 뷰와 대조한다. 페이지 경계를 넘는 슬롯도 각 페이지의
   바이트를 확인한다. 대상 메모리에서 차이를 역산하거나 슬롯을 제외하지 않는다.
4. 대상 바이트 차이는 기존대로 다시 읽어 안정성을 확인한다. 배치 후 파일과
   양쪽 헤더의 식별자·기준을 재확인한다. 기준이 배치 또는 순회 조각 사이에서
   달라지면 비교 결과·페이지 상태를 폐기하고 새 순회를 요구한다.

독립 뷰는 처리 조각마다 해제하며 전역 매핑 캐시를 추가하지 않는다. 기존 페이지·
시간·게시 예산을 유지한다. 헤더만 받는 `QualifyExecutableReference`는 제3 주소를
계속 거절하며, 파일 핸들을 확보하는 전체 순회에서 추가 근거를 확인한다.
`relocation_basis=independent_sec_image_no_execute`와 `relocation_base`를 이미지
coverage·진행 기록·코드 변경 증거에 남긴다.

`SEC_IMAGE_NO_EXECUTE`의 동작과 요구 보호 속성은
[Microsoft CreateFileMapping 문서](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createfilemappinga),
재배치 형식은 [Microsoft PE 형식 문서](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)를
확인했다. 독립 매핑은 현재 파일의 기대 재배치값을 확인하는 근거이며 최초 section의
파일 객체, 서명 신뢰성, 코드의 악성 여부를 증명하지 않는다.

## 회귀·적대적 검사

Release 빌드와 전체 자체 테스트, 핵심·레이아웃 ASan 검사가 통과했다.
`layout-asan-b.log`는 105,120개 확인에서 실패 0건이다. 직접 만든 PE32·PE32+ 파일을
실제로 매핑하며 다음을 확인한다.

- 정상 보조 뷰의 실행 영역 8,192바이트를 재배치 슬롯을 포함해 모두 비교한다.
- 일반 코드 1바이트, 재배치 슬롯만 1바이트, 페이지 경계를 넘는 슬롯의 뒷부분만
  바꾸어도 해당 변경을 검출한다.
- 임의의 제3 주소를 헤더에 넣으면 독립 기준과 불일치하므로 비교하지 않는다.
- 페이지를 읽은 뒤 헤더 기준이 바뀌면 해당 배치의 변경·정상 판정을 모두 폐기한다.
- 두 순회 조각의 재배치 기준이 달라지면 이전 페이지와 섞어 완료하지 않는다.
- 선호 주소를 이미 점유한 상태에서 같은 x64 파일을 실제 로더로 다시 로드한다.
  로더가 포인터와 헤더를 새 주소로 갱신한 뷰는 일반 매핑 주소 기준으로 모두
  검증하며, 보조 원본 뷰의 기준을 잘못 적용하지 않는다(`loader-conflict.json`).
- 기존 PE/PDB 식별자 불일치, 파일 교체, 읽기 실패, 불안정 바이트, 일반 로드 이미지
  검사와 기존 REL32 동적 재배치 검사를 유지한다.

## 실제 전체 프로세스 실행

```powershell
tools/validate-kmon-live.ps1 -AllProcessLayouts -ImageSweepFixtures -SecondaryViewFixtures -ObserveSeconds 300 -ProbeDriver -RequireQueueHealth -RequireCompletedWork -RequireImageCompletion -RequireLayoutNameAccounting -RequireFreshLayouts
```

기존 양성 5종·음성 2종에 PE32·PE32+ 보조 뷰의 정상·일반 코드 변경·재배치 슬롯만
변경하는 대조군 6종을 추가한다. 모든 생성 바이트는 실행하지 않는다. 같은 파일의
정상 첫 뷰가 완료돼도 보조 뷰 검증으로 세지 않는다. 정확한 파일·보조 뷰 주소·
재배치 기준과 양성의 1바이트 변경 위치까지 대조한다. 각 실행의 요구 범위는
13개 프로세스 대조군, 고정 이미지 52개와 보조 뷰 이미지 6개다.

기준 실행에서는 보조 뷰 6개가 모두 모호성으로 남아 비교 바이트가 0이었다.
보조 뷰의 일반 코드·슬롯 변경 양성 4종도 검출하지 못했다. 기존 대조군 7종과
큐·이름·후보 만료 검사는 통과했다. 기준 검증의 전체 결과는 실패로 보존했다.

새 대조군은 실제로 로더 목록 밖에 이미지 두 개를 매핑한다. 기준 실행에서 함께
나온 `exe_orphan_image`, `image_pe`, `resource_only_pe`, `drop_module` 기록은
그 구조를 관측한 악성 미확정 단서였다. 초기 대조군 기대에는 이들이 포함되지
않아 미예상 기록 4·5개로 집계됐다. 실제 layout의 두 파일 매핑 주소와 경로,
MEM_IMAGE·크기·아키텍처 및 `lead`·`not_established`·비교 바이트 0 조건을 확인한
경우만 검증기의 예상 구조 단서로 분리했다. 제품의 탐지 규칙이나 기록은 억제하지
않았다. 정상 보조 뷰는 코드 변경의 음성 대조군이며, 로더 밖 이미지 존재의 음성

### 배경 관측 확인

`final-a`의 `ChatGPT.exe` PID 7780에서는 `ntdll.dll` 시스템 호출 진입점 9개에
16바이트씩 변경된 두 페이지가 관측됐다. 기대 캡처를 디스크와 재배치 표로 독립
재계산해 일치하는 것을 확인했다. 관측 바이트는 즉시값 주소로 분기하는 형태였고,
9개 목적지 모두 같은 프로세스의 `ChatGPT.exe` 이미지 범위 안에 있었다.
이들은 `mapping_base` 경로의 실제 144바이트 차이이며, 보조 뷰 기준을 잘못 적용한
차이가 아니다. 변경 주체나 악성 여부는 이 사실만으로 확정하지 않는다. 기존
`observation`·`maliciousness=not_established` 기록과 캡처를 유지했다.
독립 검산은 `final-a/background-code-audit.json`, 목적지 범위는
`final-a/process-main-image.json`에 있다.

`final-b`에서는 `msedge.exe` PID 4316에서 같은 두 `ntdll.dll` 페이지의 160바이트
차이를 확인했다. 10개 분기 목적지 모두 그 프로세스의 `msedge.exe` 이미지 안에
있었고 기대 캡처도 독립 재계산과 일치했다. 두 실행의 Node·skia 메타데이터
불일치도 캡처로 다시 확인했다. Node는 타임스탬프·진입점·이미지 크기·체크섬,
skia는 체크섬이 현재 경로의 파일과 달랐다(`identity-audit.json`). 이 관측 역시
변경 주체·악성 여부·최초 section 파일 출처를 확정하지 않는다.

## 남은 범위

독립 뷰를 열 수 없거나 식별자·헤더 기준이 다르면 기존 모호성으로 남긴다.
독립 뷰의 재배치 바이트를 디스크 계산으로 확인하지 못한 페이지도 실패 범위로
남긴다. 대상 헤더가 제3 주소를 가리키는 보조 뷰에 대한 추가 검증이며 모든 로더·
임의 수동 재배치 방식의 정당성을 판정하는 기능은 아니다.

이름 수집, 후보 재확인, 이미지 순회·바이트 비교는 서로 다른 범위다. 접근 불가
프로세스·페이지, 기존 동적 재배치 제외 구간과 이미지 작업 캐시·시간 한도는
유지한다. 통제한 대조군에서의 탐지 결과를 호스트 전체의 누락·오탐 부재로 확대하지 않는다.

최종 두 실행에서 프로세스 질의 불가 상태는 각각 13개였다. 캡처 계층의 읽기
실패는 12,288·540,672바이트, 사전에 확인한 읽기 불가 범위는 각각 344,064바이트로
별도 기록했다. 이 범위를 보조 뷰 검증 성공에 포함하지 않는다.

직전 `vctip`의 자연 발생 보조 뷰는 이번 두 실행의 이미지 비교 범위에서 관측되지
않았다. 따라서 그 프로세스의 모든 보조 뷰가 해결됐다는 주장은 하지 않는다.
원래 파일의 독립 매핑 실험과 같은 특성을 갖는 실제 PE32·PE32+ 대조군을 사용해,
전체 프로세스 KMON 안에서 정상 비교와 변경 검출을 반복 검증했다.
