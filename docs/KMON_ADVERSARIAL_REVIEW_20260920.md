# Kmon 적대적 코드 리뷰 — 2026-09-20

`e1babba66b331d73b35b45e5c7cd4d6a591e45eb`의 전체 실행 페이지·PTE 검사와 기존 참조 수집 경로를 재검토해 다섯 종류의 문제를 수정했다. 용량 초과 순회, 사건 갱신 순서, 잘못된 페이징 엔트리는 수정 전 실패를 재현했다. 실제 읽기 PFN과 늦은 슬롯 변경은 데이터 흐름을 검토하고 해당 판정의 회귀 시험을 추가했다. 최종 수정 범위를 다시 검토하고 Release/Debug 검사를 통과한 뒤 추가 조치가 필요한 문제는 발견하지 못했다.

## 발견한 문제와 수정

| 문제 | 영향 | 수정과 검증 |
|---|---|---|
| P1: 용량 초과 목록에서 범위가 반복 퇴출됨 | 같은 범위를 계속 관측해도 시작 페이지만 예약하고 꼬리 페이지에 도달하지 못함 | 같은 우선순위의 진행 중인 범위를 보호하고 완료 지점 뒤부터 후보 수용 순서를 순환. 정순·역순·16개 고정 seed의 섞인 목록에서 전체 페이지 도달 확인 |
| P1: 실제 물리 읽기에 사용한 PFN을 버림 | 번역 A, 실제 읽기 B, 번역 A인 경우 B의 바이트에 A의 PFN을 연결할 수 있음 | 최초 페이지 읽기와 캡처의 실제 PFN을 보존하고 후보·전후 번역과 모두 대조. 불일치와 알 수 없는 표본을 섞은 판정 회귀 추가 |
| P1: 캡처 중 슬롯·프로세스·주소 공간 변경을 뒤늦게 발견함 | 먼저 등록한 hop 참조나 finding이 남아 무효화된 경로를 계속 제시할 수 있음 | 참조를 임시 보관하고 최종 슬롯·인스턴스·EPROCESS/DTB 검사 뒤 공개. 실패 시 경로 전체를 보류하고 coverage로 처리. 늦은 슬롯 변경 판정 회귀와 호출 경로 검토 |
| P2: 기존 사건의 갱신이 정렬 위치에 반영되지 않음 | 최근에 재관측한 증거가 출력 상한에 걸려 오래된 증거 뒤로 밀림 | 기존 ID를 유지하면서 갱신한 참조를 최신 위치로 이동. A, B, A 순서와 출력 상한 1로 재현·검증 |
| P2: 예약 비트가 잘못된 엔트리를 실행 가능으로 인정함 | 소프트웨어 번역 성공만으로 실제로는 유효하지 않은 페이지를 실행 증거로 승격할 수 있음 | PML5E/PML4E의 PS와 큰 페이지의 예약 주소 비트를 거부. 정상 PAT를 허용하는 양성 대조와 세 종류의 음성 회귀 추가 |

순회 수정의 첫 번째 시도는 진행 중인 범위만 보호했다. 추가 시험에서 목록의 첫 비상주 범위가 빈자리를 계속 차지하는 실패가 남아, 마지막 완료 키 뒤부터 수용 순서를 순환하도록 다시 수정했다. 삭제 위치 앞뒤에 따라 다음 순회 차례가 바뀌지 않도록 커서도 조정했다. 비소유 후보가 이미지 재검사를 대체하는 우선순위는 유지한다. `ranges_deferred`는 용량 정책 때문에 수용을 미룬 관측 횟수이며, 잘못된 입력을 나타내는 `ranges_rejected`와 구분한다.

PFN 일치 함수는 알려진 표본 사이의 모순을 검사한다. 모두 미확정인 표본이 일치 함수를 통과하더라도 PFN이 확인된 것으로 처리하지 않는다. 호출 경로는 캡처 전후의 알려진 매핑과 실행 권한도 별도로 요구한다. 이 시험은 PFN 판정 로직을 검증한 것이며 실제 커널에서 A→B→A 교체 경쟁을 재현한 결과는 아니다.

슬롯 재검증은 경로 해석 전후에 더해 캡처가 끝난 뒤에도 수행한다. 중간 hop에서 슬롯·프로세스·주소 공간 불일치를 확인하면 이후 검사에서 원래 값으로 돌아와도 해당 경로의 참조를 공개하지 않는다. 이미 확보한 과거 바이트와 캡처 파일은 남을 수 있다. 전체 장치 수집기를 가짜 드라이버로 실행한 통합 경쟁 시험은 이번 검증에 포함하지 않았다.

예약 비트 검사는 [Intel SDM Volume 3의 IA-32e 페이징 규칙](https://cdrdv2-public.intel.com/851064/325384-087-sdm-vol-3abcd.pdf)에 근거한다. PML5E/PML4E의 bit 7, 1 GiB leaf의 bits 29:13, 2 MiB leaf의 bits 20:13을 확인한다. 큰 페이지 PAT의 bit 12와 4 KiB PTE PAT의 bit 7은 그대로 허용한다. CPU별 MAXPHYADDR나 추가 실행 제어를 모두 검증한다는 뜻은 아니다.

소유 fixture의 clean/modified/text/jit 모드에서 Kmon 메인 이미지 비교가 찾은 수정 페이지는 각각 0/1/1/0이다. PE-sieve v0.4.1.1의 해당 이미지 `code_scan` 상태는 0/0/1/0이며 오류는 없었다. 정상 private RX fixture는 이미지 비교 범위 밖이므로 이 결과로 private 코드 탐지율을 계산하지 않는다. 비교 범위와 옵션은 [헌팅 문서](KMON_CROSS_DOMAIN_HUNTING.md#재현-검증과-외부-비교)에 있다.

이번 수정은 사용자 프로그램과 검사 코드에 한정된다. 드라이버 소스·ABI는 바뀌지 않았으며 드라이버를 설치하거나 커널 callback을 변경하지 않았다. ASan은 핵심·헌팅 검사 실행 파일에 적용했으며 전체 KnLiveDbg 프로그램에 적용한 결과는 아니다. 파서 전용 ASan 대량 시험은 이전 확장 검증 기록에 있고 이번에는 다시 실행하지 않았다.

검증 로그·실행 파일·수정 소스의 SHA-256과 구성별 결과는 [기계 판독용 검증 기록](../research/kmon-adversarial-review-20260920.json)에 있다. 로그와 fixture 원본은 로컬 `.build` 아래에 보존하며 저장소에는 요약과 hash만 기록한다. 소스 hash는 UTF-8/LF 정규화 기준이다. 이전 [확장 검증 기록](../research/kmon-coverage-validation-20260920.json)은 당시 결과로 보존했다.

## 실제 환경에서 확인할 범위

사용자 요청에 따라 실제 VM·게임핵 검증은 사용자에게 남긴다. OS별 PDB 레이아웃, 실제 슬롯 교체와 프로세스 종료 경쟁, DTB/PFN 변경, 긴 시간의 정상 시스템 오탐과 스캔 사이에만 나타나는 코드가 대상이다. 이번 반복 검토의 종료 조건은 재현된 실패의 해결, 수정 경로 재검토와 지정한 로컬 검사의 통과다. 모든 환경에서의 무누락이나 경쟁 제품 대비 탐지율을 입증한 결과는 아니다.
