# 실제 vctip의 System.Data 보조 뷰 검증 (2026-10-24)

기준 커밋은 `5cb6e31`이다. [직전 검증](KMON_SECONDARY_IMAGE_VALIDATION_20261023.md)은
소유한 PE32·PE32+ 대조군으로 재배치 기준을 확인했지만, 실제 vctip의 해당 뷰를
관측하지 못했다. 이번에는 설치된 MSVC가 생성한 실제 프로세스에서 재현했다.
증거는 날짜가 바뀌기 전에 만든 `.build/kmon-vctip-20261023`에 보존한다.

## 실제 재현과 독립 비교

설치된 MSVC `14.44.35207`의 `Hostx64/x64/cl.exe`로 작은 C++ 파일을 컴파일하면
64비트 vctip과 GAC_64의 단일 System.Data 뷰가 나타났다. 이 작업이 생성한
프로세스만 생성 시각·경로를 재확인하여 종료하고 `Hostx86/x86/cl.exe`로
같은 파일을 컴파일하자 32비트 vctip에 GAC_32의 두 뷰가 나타났다. 이후 프로젝트
빌드가 사용하는 `HostX86/x64` vctip에서도 같은 현상을 확인했다. 명령행·부모 PID·
생성 시각을 각 `*-trigger.json`에 기록했다. 대상에 주입하거나 메모리를 수정하지 않았다.

파일은 다음과 같다.

```text
C:\Windows\Microsoft.NET\assembly\GAC_32\System.Data\v4.0_4.0.0.0__b77a5c561934e089\System.Data.dll
SHA256 d4eb64d395384b8cdcee4934662c3ad92db443f604f759e684d77cbff16ad2e0
```

디스크 선호 주소는 `0x10000000`이다. 보조 뷰의 실제 주소는 헤더 ImageBase와
다르며, 정상 로더 뷰 주소와 두 헤더의 ImageBase는 일치한다. 재생성한 프로세스마다
매핑·재배치 주소가 달라져 고정 주소에 의존하지 않았다. 각 뷰의 PE 실행 섹션은
3,414,016바이트, 834개 페이지 범위이며 HIGHLOW 재배치 슬롯 9,129개를 포함한다.
독립 재계산에서는 재배치 슬롯이나 다른 바이트를 제외하지 않는다.

`tools/validate-kmon-vctip.py snapshot`은 파일을 쓰기·교체 공유 없이 열고 PE32를
별도로 해석한다. 대상 페이지를 두 번 읽으며 매핑·헤더와 프로세스 생존을 확인하고,
기대·관측 바이트와 SHA256을 저장한다. 실행 전후 스냅샷은 두 뷰 모두 차이 0이었다.
이것은 시점별 비원자적 관측이며 실행 주체나 전체 프로세스의 정상성을 증명하지 않는다.

## 발견한 문제와 수정

이름 수집과 레이아웃 후보 처리가 성공해도 이미지 작업의 2,048개 캐시가 차면
늦게 발견한 뷰가 등록되지 않았다. 기존 경고는 최초 한 건을 PID 0·빈 image로
남겨 대상별 누락을 확인하기도 어려웠다. 기준 바이너리 `5cb6e31`은 13개 대조군을
통과했지만 실제 System.Data의 두 뷰에는 이미지 비교 기록이 없었다.

1. 전체 작업 상한 2,048개를 유지하면서, 감시 PID·이름이 있으면 아직 감시 이미지가
   사용하지 않은 최대 256개 슬롯을 예약한다. 진행 중인 배경 순회는 버리지 않는다.
   예약 공간을 감시 이미지가 쓰면 배경 등록 한도도 늘어난다.
2. 등록 보류 시도 수를 전체·감시 대상으로 나누어 pipeline에 기록한다. 최대 5초에
   한 번 실제 PID·생성 시각·파일·매핑 주소·등록 한도를 표본으로 남긴다. 이 수치는
   서로 다른 누락 이미지 수가 아니다.
3. 완료 작업을 캐시에서 제거할 때 원래의 30초 재검사 대기도 사라지던 문제를
   수정했다. 최대 4,096개의 작은 파일 식별자·시각 기록으로 대기를 유지한다.
   경로 별칭은 전체 128비트 파일 ID·볼륨·파일 변경 시각으로 확인한다. 프로세스
   세대·매핑 주소가 다르거나 파일이 바뀌거나 확인할 수 없으면 새 검사를 허용한다.
   이 기록에는 PE 범위나 바이트 판정을 보관하지 않으며 `OwnedVerified`를 재사용하지 않는다.

등록 예약이 가득 찬 뒤의 추가 감시, 많은 동시 감시 이미지, 배경 이미지 전체의
완료까지 보장하지는 않는다. 대기 기록이 한도에 도달하면 저장을 생략하여 더 이른
재검사를 허용한다. 페이지·시간·게시 예산과 실제 재배치 검증 조건은 유지한다.

## 최종 실제 프로세스 실행

동일 바이너리의 동시 대조군 검증과 별도로, 전체 호스트 레이아웃 수집을 유지한 채

## 탐지 대조군과 다른 이미지의 관측

최종 바이너리의 `final-b`에서 양성 9종·음성 4종이 모두 통과했다. 요구한 이미지
순회 58개가 완료됐고 예상 밖 대조군 이벤트는 0이었다. 6개 보조 이미지 대조군은
각 8,192바이트를 제외·읽기 실패 없이 비교했다. PE32·PE32+의 일반 코드 1바이트 및
재배치 슬롯 안의 1바이트 변경을 모두 탐지했고 두 clean 대조군의 코드 변경 관측은
0이었다. 양성 보조 뷰의 캡처 52쌍을 디스크 재배치로 별도 재구성해 기대 페이지와
정확한 변경 위치가 일치함을 확인했다. 가져온 시스템 DLL의 기존 제외 구간까지
없어졌다는 뜻은 아니다. 이 실행에서 실제 vctip의 두 큰 뷰는 앞 표처럼 partial로 남았다.

`actual-a`, `actual-b`, `final-b`의 대조군 외 코드·정체성 관측도 별도로 검사했다.

- 실제 vctip의 `clr.dll`은 각 실행에서 229바이트의 실제 차이가 있었다.
  기대 페이지 4,096바이트를 디스크와 재배치로 재계산했고, 캡처 차이가 보고된
  10개 범위와 정확히 일치했다. 런타임 초기화 코드와 유사한 패턴이라는 기존
  [분석](KMON_LAYOUT_FRESHNESS_VALIDATION_20261023.md)을 원인 확정으로 취급하지 않는다.
- `actual-a`의 USER32 관측 1건과 `actual-b`의 2건은 동일한 페이지의 두 범위
  `846612:8`, `846640:8`에서 실제 16바이트가 달랐다. 독립 기대 페이지와 보고 범위가
  모두 일치했다. 변경 주체·악성 여부는 이번 검증으로 확정하지 않았다.
- 세 실행의 기존 node 프로세스에서 `node.exe`의 timestamp·진입점·이미지 크기·checksum,
  `skia.node`의 checksum이 현재 경로의 디스크 파일과 실제로 달랐다. 저장한 PE 헤더를
  별도 해석하여 확인했으며 이 파일들을 잘못된 기준으로 바이트 비교하지 않았다.

이들은 `maliciousness=not_established`인 관측으로 유지했다. System.Data의 재배치
계산 오류나 대조군 오탐으로 집계하지 않았고, 이름에 따른 제품 허용 목록도 추가하지
않았다. `background-code-audit.json`, `identity-audit.json`, `secondary-audit.json`과
원본 캡처에 근거를 보존했다.

## 검증 절차와 범위

```powershell
python tools/validate-kmon-vctip.py snapshot --pid <PID> --out .build/vctip-before
tools/validate-kmon-live.ps1 -AllProcessLayouts -ObservedProcessId <PID> -SkipFixtures -ObserveSeconds 300 -ProbeDriver -RequireQueueHealth -RequireCompletedWork -RequireLayoutNameAccounting -RequireFreshLayouts -OutputDirectory .build/vctip-live
python tools/validate-kmon-vctip.py snapshot --pid <PID> --out .build/vctip-after
python tools/validate-kmon-vctip.py audit --run .build/vctip-live --before .build/vctip-before/snapshot.json --after .build/vctip-after/snapshot.json
python tools/test-kmon-vctip-audit.py
```

Release 빌드와 전체 자체 테스트를 통과했다. 파이프라인 자체 테스트는 캐시 포화,
미완료 순회 유지, 예약 공간 회수, 대기 만료, 경로 별칭, 다른 파일·프로세스 세대·주소,
128비트 파일 ID 변경, 대기 기록 상한을 다룬다. Python gate의 15개 검사는 대상 누락,
로더 뷰만 완료, 잘못된 파일·세대·기준, 캡처 변조, 일부 바이트 제외, 큐 손실을 거절한다.

`vctip-validation.json`은 두 뷰 각각에 올바른 재배치 기준으로 실행 섹션 전체의
완료 기록이 있고, 건너뜀·실패 바이트와 System.Data 변경 관측이 0이어야 통과한다.
전후 파일·뷰·프로세스 식별자와 독립 바이트 해시도 일치해야 한다. 추가 대조군
검증과 호스트의 다른 이미지 관측은 이 결과와 구분한다. 전체 호스트의 모든
프로세스·모든 시간에 대한 탐지 누락·오탐 0을 주장하지 않는다.
