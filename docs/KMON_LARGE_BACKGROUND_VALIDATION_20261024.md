# 대형 배경 이미지와 실행 간 검사 범위 검증

기준 커밋은 `eb30cae`다. 실제 x86 VCTIP와 양성 9개·음성 4개 대조군을 유지하고
콘솔 자식까지 27개 PID를 감시한다. 전체 프로세스 모드의 관찰 시간은 매번 600초다.
원본 로그·스냅샷·캡처는 `.build/kmon-large-background-20261024`에 보존한다.

## 원인과 변경

이전 수정본 `kmon-background-names-20261024/final-b`의 종료 캐시에는 실행 구간이
16MiB 이상인 배경 이미지 31개가 있었다. 약 270MiB의 `msedge.dll` 등은 7~11번의
전용 차례를 받고 수 MiB만 비교한 상태였다. 커서는 보존됐지만 시간 예산과 작업 간
경쟁으로 꼬리 구간에 도달하지 못했다. 일부 Node 이미지는 실제 PE 식별자가 달라
진행할 수 없는 별도의 공백이었다.

대형 이미지의 우선 차례는 `LastSweepMs`가 가장 오래된 작업을 골랐다. 이 시각은
레이아웃 후보 등에서 수행하는 짧은 부수 검사로도 갱신된다. 같은 횟수를 배정해도
25ms 안에 읽는 페이지 수가 다르고, 부수 검사 순서가 다음 우선순위에 영향을 줬다.
수정본은 이 차례에서 최초 순회 커서가 가장 덜 진행된 작업을 고른다. 동률에서는
기존 검사 시각을 사용한다. 동일성 확인에 실패해 커서가 계속 0인 작업은 일반 회전에서
재시도한다. 이 작업을 완료·정상으로 간주하거나 삭제하지 않는다.

감시/배경과 최초/재검사의 배분, 일반/대형/짧은 잔여 구간의 배분, 25ms 예산,
1,024페이지 상한, 게시 상한 및 2,048개 캐시 상한은 유지한다.
`image_bulk_progress_turns`와 `bulk_progress_turns`는 선택 횟수이며 성공·완료 횟수가 아니다.

일반 실행 페이지는 바이트가 모두 같아도 페이지마다 비트 마스크와 개별 바이트
순회를 거쳤다. 재배치를 적용한 예상 바이트와 실제 읽은 바이트가 정확히 같고,
로더 변경·동적 재배치 제외·REL32 대체 구간과 겹치지 않으면 전체 범위를 한 번에
비교 성공으로 기록한다. 변경 페이지와 제외 구간은 기존 경로를 사용한다.
파일·프로세스·매핑·이미지 식별자의 검증과 마지막 재확인은 그대로 수행한다.
같은 바이트라는 이유만으로 제외 구간의 검증 상태를 높이지 않는다.

## 검증 방법

- 네이티브 self-test: 최근 부수 검사를 받은 낮은 커서 우선, 동일성 실패 작업의
  일반 재시도, 기존 일반/대형/완료/재검사 배분을 확인한다. 값이 같은 로더·동적
  제외 바이트 및 지원하지 않는 REL32 구간도 미검증으로 남아야 한다.
- `tools/benchmark-kmon-image-sweep.cpp`: 실행하지 않는 합성 32MiB PE를 읽어
  4번 순회한다. 마지막 순회에서는 맨 끝 한 바이트를 바꿔 반드시 탐지해야 한다.
  프로세스 원격 읽기와 전체 KMON 스케줄링 비용은 포함하지 않는 별도 비교 시험이다.
- `tools/measure-kmon-image-coverage.py`: 실제 게시한 비교 주소를 부팅·PID·생성 시각별로
  합쳐 중복을 제거한다. 범위에서 생략된 비교 바이트가 있으면 정확한 범위 비교를 거부한다.
  비교 바이트가 0인 식별된 프로세스도 공통 집단에 포함한다.
- `--fixed-cohort`: 모든 입력 실행에서 식별된 공통 배경 프로세스로 분모를 고정한다.
  두 실행의 공유/합집합 주소 비율(Jaccard)과 한쪽에서만 검사된 바이트를 계산한다.
  둘 다 검사량이 0이면 재현성 100%로 표현하지 않는다. 관련 반례 8개를 별도로 검사한다.

관측 사이의 같은 주소 재사용까지 구별하는 측정은 아니다. 호스트의 전체 미검사
바이트 분모나 실시간 탐지의 완전성을 주장하지 않는다. 13개 대조군의 누락·오탐과
별도로, 배경에서 보고한 실제 코드·PE 차이는 저장 캡처를 독립 재구성해 대조한다.

```powershell
tools/build.ps1 -Configuration Release
x64/Release/KnLiveDbg.exe --self-test all
tools/validate-kmon-core.ps1 -Configuration Release
python tools/test-kmon-image-coverage.py
tools/validate-kmon-live.ps1 -AllProcessLayouts -ImageSweepFixtures -SecondaryViewFixtures `
    -ObservedProcessId $actualVctipPid -ObserveSeconds 600 -ProbeDriver `
    -RequireQueueHealth -RequireCompletedWork -RequireImageCompletion `
    -RequireLayoutNameAccounting -RequireFreshLayouts `
    -MonitorExecutablePath $frozenMonitor -OutputDirectory $run
python tools/measure-kmon-image-coverage.py $baselineA $baselineB $candidateA $candidateB --fixed-cohort
```

## 결과

Release 빌드, `--self-test all`, 별도 `validate-kmon-core.ps1` 및 범위 비교 반례 8개가
통과했다. 이미지 검증기의 변경된 반례는 별도 core 하네스에서 실행한다.
core 결과는 이미지·재배치·범위·매핑 재사용 검증 PASS, 합성 hunting 11,326개,
페이지 54개, 오탐 대조 49개 통과였다. 실제 악성 표본 탐지율로 취급하지 않는다.

| 대상 | SHA-256 |
|---|---|
| 기준 `KnLiveDbg-background-F8C964C0.exe` | `F8C964C05BAABB69DDD5AEB812B3F4AF0888E8D3B2985A5276E4789BF1813D6C` |
| 수정 `KnLiveDbg-large-F77EB918.exe` | `F77EB918D123DCA747D2FC9311E8F98E4667839255237A7AF76231B7EA3F6844` |
| 대조군 실행 파일 | `ADEE3A4C4DCE154BDFA3A80618361F7E34B6930B41E3A2603179C5A1D2944B67` |

모니터는 이름을 달리해 고정했고 소스 4개 파일의 빌드 시점 해시와 실행 전 해시를
대조했다. 빌드 및 별도 core 컴파일로 생긴 VCTIP 보조 프로세스는 정확한 경로와
생성 시각이 해당 빌드 구간에 속하는지 확인해 정리했다. 각 실제 VCTIP 실행은
System.Data.dll 두 뷰의 준비를 확인하고 전후 독립 스냅샷을 수집한다.
관찰 중에는 다른 KMON 세션, 빌드, 대규모 로그 분석을 병행하지 않는다.

분리 비교 시험은 기준·수정·수정·기준 순서로 실행했다. 각 실행의 첫 순회를 제외한
정상 32MiB 순회 시간은 기준 93.166~108.503ms(중앙값 95.135ms), 수정본
51.441~54.165ms(중앙값 52.165ms)였다. 중앙값 기준 45.17% 감소했다.
각 정상 순회의 읽기 횟수 8,228회, 비교량 33,554,432바이트는 동일했다.
각 실행의 마지막 변조 순회에서도 마지막 페이지의 한 바이트 차이를 탐지했고,
재확인 읽기를 포함한 8,229회의 읽기를 수행했다. 이 수치를 전체 KMON 처리량 증가율로
대입하지 않는다. 컴파일은 양쪽 모두 `/O2 /std:c++17 /EHsc /DNOMINMAX`를 사용했다.

### 실행 간 범위 편차

같은 기준 바이너리를 연속 실행했던 이전 기록
`kmon-background-names-20261024/final-a`, `final-b`와 이번 수정본 두 실행을 비교했다.
네 실행 모두에 관측된 배경 프로세스 194개로 분모를 고정했다. 같은 부팅·같은
프로세스 세대여도 관측 사이의 미발견 매핑 교체까지 배제하는 것은 아니다.

| 연속 실행 두 번의 비교 | 기존 바이너리 | 수정 바이너리 |
|---|---:|---:|
| 공유한 비교 주소 바이트 | 685,869,956 | 676,376,684 |
| 비교 주소 합집합 바이트 | 1,310,933,144 | 1,268,558,064 |
| 주소 겹침 비율 (Jaccard) | 52.32% | 53.32% |
| 한쪽에서만 비교한 주소 바이트 | 625,063,188 | 592,181,380 |

겹침 비율은 약 1.00%p 높아졌고 한쪽에서만 비교한 양은 5.26% 작아졌다.
다만 공유 바이트와 합집합 자체도 작아졌다. 두 실행씩의 관측 결과이므로 전체
검사 범위의 재현성을 크게 높였거나 통계적으로 확정했다고 주장하지 않는다.

시간 간격이 더 긴 이전 `final-b`와 새 `baseline`의 비교도 숨기지 않고
`long-interval-repeatability.json`에 남겼다. 같은 194개 집단에서 이 기준 쌍은
47.60%, 수정 쌍은 53.32%였다. 실행 간격이 다른 비교이므로 위의 연속 실행 비교보다
강한 개선 근거로 삼지 않는다. 새 기준 대비 검사량 증가는 별도 195개 집단의 결과다.
